# 术语回潮检查的反模式表（R13 期2）
#
# 单一来源：`gateway/tests/terms.test.ts` 与 `ios/tests/TermsTests.swift` 读同一份，
# 结构上不可能漂移。
#
# 格式（分号分隔，`#` 开头为注释）：
#   规则    词;正则;建议;理由
#   自查样本 expect-hit;<一句应当被拦的话>   或   expect-pass;<一句应当被放过的话>
#
# 三条纪律：
#   1. **只拦「词 + 搭配」，不拦词本身。** 直接论据：期1 按词替换留下 60 处误伤，
#      其中「承载」的中文通用动词形占 9 处（「承载的是…」「承载 + 名词」）。
#   2. **正向枚举优于负向断言。** 分不清的搭配不入表 —— 宁可漏，不可误伤。
#   3. **不写「场景」。** 它 102 处落点里 83 处是「使用场景 / 业务场景 / 压测场景」，
#      按词拦的误报率 94%，扫出来只会是一堆要写的豁免。
#
# 已知的漏（明知不做，别当它被覆盖了）：「承载」的通用动词形若被误换成「组网/传输」
# 且不留重复词（「头部单独组网生命周期」），本表拦不住 —— 那是语义判断，靠人读。
#
# 正则方言：两端都要求**无歧义**的 JavaScript / ICU 交集语法。禁用 POSIX 字符类
# （`[[:alpha:]]`）与 `\p{...}` —— 前者 JS 当字符集、ICU 当 POSIX 类，后者在无 `u`
# 标志的 JS 里被降级成字面量，同一份表会变成两个意思。
